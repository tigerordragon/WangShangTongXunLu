# 项目规范

## 项目大纲

本项目是一个 Java Web 网上通讯录系统，目标是完成学生注册、审核、登录、通讯录维护和同学通讯录查询。项目以模块方式推进，每个模块对应独立的后端接口、页面入口和验收结果。

项目功能分为五个模块：

1. 学生注册与审核状态管理
2. 学生登录与登录信息记录
3. 学生完善自己的通讯录信息
4. 学生查询其他同学的通讯录信息
5. 管理员账户与专业信息维护

模块文档放在 `docs/2` 到 `docs/6`，每份文档描述功能目标、角色边界和验收结果。

## 代码提交规范

每个具体任务需要开启一个 `branch`，不允许直接向 `main` 分支提交。

每次提交只处理一个明确的小任务。提交前确认代码能正常构建，相关页面和接口能完成对应功能。

提交信息采用 `Conventional Commits`，格式为 `type: 描述`，描述使用简洁中文。

```text
type: 本次完成的内容
```

示例：

```text
feat: 完成学生注册接口和待审核状态写入
feat: 记录最近登录时间和登录次数
fix: 修复学生登录状态判断
docs: 更新学生通讯录查询说明
```

常用类型：

- `feat`：新增功能
- `fix`：修复问题
- `docs`：修改文档
- `chore`：调整配置、目录或构建文件

## 单元测试要求

后端核心逻辑需要配套单元测试，重点覆盖登录校验、审核状态判断、通讯录信息保存、查询条件过滤等规则。

新增功能时，至少为主要正常流程写 1 个测试。修复问题时，先补能复现问题的测试，再修改代码。

测试文件放在 `src/test/java`。测试类命名使用 `被测类名Test`，测试方法名要能说明验证场景。

提交前运行：

```bash
mvn test
```

测试通过后再运行完整构建：

```bash
mvn package
```

## 分支代码提交流程

开始任务前，从 `main` 创建任务分支：

```bash
git switch main
git pull
git switch -c feat/student-register-audit
```

开发完成后，提交前确认项目可以构建：

```bash
mvn package
```

之后在任务分支提交代码：

```bash
git status
git add .
git commit -m "feat: 完成学生注册接口和待审核状态写入"
```

推送任务分支到远端：

```bash
git push -u origin feat/student-register-audit
```

推送后在 GitHub 创建 Pull Request，目标分支选择 `main`。每个人按负责人模块提交 Pull Request，由另一同学 Review 后合并到主分支。

提交前检查：

1. `mvn test` 确认单元测试通过。
2. `mvn package` 确认项目可以构建。
3. 页面和接口完成当前模块的基本流程。
4. 提交信息能说明本次改动内容。
